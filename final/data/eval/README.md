# Evaluation Framework

This folder holds everything needed to measure how good the chatbot actually is,
as required by the assignment brief (a working pipeline alone is not enough).

## Files here

- **`topics.csv`** — the test question set (28 questions). Most are real
  food-safety/allergen questions the KB should be able to answer. The last two
  (Q27, Q28) are deliberately **off-topic** ("capital of France", an election
  question) — they exist to test whether the chatbot correctly says "I don't
  know" instead of making something up when a question is outside its knowledge
  base.
- **`pool.csv`** — generated by `python data.py`. For every question, the top-10
  retrieved passages, ready for a human to mark relevant or not.
- **`qrels.csv`** — the *judged* version of the pool (only the passages a human
  has confirmed are relevant), used to compute retrieval quality.
- **`../../target/eval_results/generation_review.csv`** — generated by
  `python eval.py generation`. Every question's actual chatbot answer, with
  two blank columns for a human to fill in.

## Step-by-step workflow

1. **Build retrieval runs** (from `src/retrieval/`):
   ```
   python search.py         # dense (FAISS) retrieval run
   python prepare_bm25_corpus.py && bash index-bm25.sh && python search_bm25.py   # optional BM25 comparison
   ```
2. **Build the judgment pool**:
   ```
   python data.py
   ```
   This creates `pool.csv`. Open it in Excel/Google Sheets.
3. **Judge relevance by hand.** For every row, put a number in the `relevance`
   column:
   - `2` = this passage fully answers the question
   - `1` = partially relevant
   - `0` / blank = not relevant
   This is the one step that genuinely has to be done by a person — it's what
   "ground truth" means. Split the 28 questions across your 4 team members so no
   one person has to judge all of them (roughly 7 each).
4. **Turn the judged pool into qrels.csv**:
   ```
   python -c "from data import build_qrels_from_judged_pool; build_qrels_from_judged_pool()"
   ```
5. **Compute retrieval metrics (nDCG)**:
   ```
   python eval.py retrieval ../../data/eval/qrels.csv ../../target/runs/rag-dense-faiss.txt ../../target/runs/rag-bm25.txt
   ```
6. **Compute generation coverage + build the manual review sheet**:
   ```
   python eval.py generation
   ```
   This prints the auto-flagged "% unanswered" and writes
   `target/eval_results/generation_review.csv`. Open that file and fill in:
   - `faithful_to_sources` (1/0) — is every claim in the answer actually backed
     up by the retrieved passages, with nothing made up?
   - `sources_correct` (1/0) — do the cited passages actually contain what the
     answer says they do?

Report the resulting percentages/nDCG numbers in Section 3 (Findings) of your
written report.
